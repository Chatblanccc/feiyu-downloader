Feather SeedVR2 3B local worker
=============================

This is an optional, offline enhancement engine. Do not bundle its model weights
or a development virtualenv into the base application. The host installs a
portable runtime and verified models in Application Support, then supplies their
absolute paths. No video is uploaded. No model is downloaded by this worker.

Compatibility / resources
-------------------------
Actual inference requires Apple Silicon, macOS 14+, MPS, at least 32 GiB unified
memory, and >=4 GiB currently available memory. PyTorch must be 2.14 or newer;
the evaluated runtime used torch 2.14.1 / torchvision 0.29.1. A version upgrade
still needs acceptance on real footage, especially on a different Mac/GPU.

worker.py and resource_guard.py must be installed together in the same directory.
The host must give this engine its own budget: min(physicalMemory*0.70, 23 GiB).
The worker accepts 20..23 GiB, with an additional safety guard: stop after three
2-second samples with <2.5 GiB available, process-tree RSS above budget, or
>1.5 GiB additional system swap. These are safeguards, not a promise that every
clip fits. Existing unrelated swap is not counted as new swap from this run.
The guardian is a separate child process in the host's existing group. It never
imports torch or calls MPS allocator statistics. It checks the exact parent PID
and creation time, samples OS memory and swap, and emits heartbeat NDJSON with a
target interval of2 seconds. Reports include actual sample count and maximum
observed gap; OS scheduling can delay the target. GPU allocator peaks are marked
unavailable rather than reported as zero. If a limit persists, only the verified
parent receives TERM; if native work prevents acknowledgement for10 seconds,
that same verified parent receives KILL. Swift retains group-wide child cleanup.

MPS high/low watermarks are forced to 0.7/0.5 before torch import. MPS computation
is BF16 with FP16 model storage, SDPA, VAE tile 512/overlap64, four CPU threads,
and no automatic CPU fallback. Model caching and torch.compile are disabled.

Interface
---------
python worker.py repair --input /absolute/input.mp4 --output /absolute/new.mp4
  --report /absolute/worker-detail.json
  --ffmpeg /absolute/ffmpeg --ffprobe /absolute/ffprobe
  --models-dir /absolute/models --upstream-dir /absolute/pinned-source
  --enhance true --repair-mosaic false --performance quality
  --output-size hd720 --memory-budget 24051816857

The last budget is 22.4 GiB, the 70% budget for a 32 GiB machine.
FFmpeg / FFprobe must be executable absolute paths. FFmpeg needs raw BGR decode,
fps/scale filters, h264_videotoolbox encode, AAC encode and MP4 muxing.

Compatible old host arguments: repair, --input, --output, --report, --ffmpeg,
--ffprobe, --enhance, --repair-mosaic, --performance, --output-size,
--memory-budget. Enhancement must be true; mosaic repair must be false.
--performance is reported for compatibility; it does not silently select a
different model or quality preset. Host UI must not imply three Seed speed modes.

Output sizing: source preserves original display dimensions; hd720 fits low
resolution footage to landscape1280x720 / portrait720x1280 without shrinking
already larger input; fullHD uses the existing landscape1920x1080 / portrait
1080x1920 behavior. Aspect ratio is preserved to even pixel dimensions. Internal
inference short side defaults to720 for source/hd720,1080 for fullHD; long edge
is limited to1280/1920 respectively. The worker reports this separately. A larger
source can therefore be internally downsampled and resized back on export.

Additional bounded tuning arguments: --resolution720|1080, --batch-size9
(4n+1,5..33), --chunk-size33 (33..96), --temporal-overlap3.
Pass argument values separated by spaces (e.g. --resolution 720).
The 33-frame tuning experiment reduced one observed seam but still changed fine
texture and small symbols. These results provide no guarantee of authenticity or
temporal stability. Real worker export and longer footage remain acceptance gates.

Streaming / cancellation / validation
-------------------------------------
The adapter imports _process_frames_core from the pinned CLI; it never calls
upstream main(), video export or implicit downloader. Each outer input window
contains33 frames by default (hard maximum96), including context. It retains three enhanced tail
frames and three raw source context frames. The next window re-infers those
same frames; the TWO ENHANCED RESULTS are linearly blended over the overlap.
Each source frame is encoded once. This fixes context-prepend-and-crop without
pretending it guarantees temporal stability. At most one bounded window and
its bounded inference intermediates are held; there is no whole-video list or
PNG sequence on disk. Input larger than the inference limit is scaled during
decode to bound the raw input window as well.

FFmpeg normalizes input VFR to the source average CFR and applies rotation.
The worker preserves all original audio tracks as AAC, removes the now-applied
rotation metadata, validates decoded output frame count, dimensions, FPS,
duration and audio-track count, and confirms the source file's size/mtime/inode
did not change. Odd dimensions, non-square pixels, non-right-angle rotation and
HDR are rejected with an explicit message pending dedicated acceptance.
Temporary MP4/logs are removed on failure. Final output uses Darwin's exclusive
atomic rename to a previously nonexistent destination. Filesystems that reject
the exclusive-rename flag use a bounded exclusive copy inside the host's private
staging folder; the host only publishes the verified folder. It never overwrites.

All spawned processes inherit the Swift host's process group. The worker does
not setsid/start_new_session or kill an external group. TERM/INT terminates its
own registered FFmpeg/FFprobe children, waits, escalates only those children if
necessary, emits cancelled (resource guards emit error), and leaves the source
untouched. The Swift host must still retain its group-wide cancellation guard.

stdout is strict NDJSON: progress/completed/error/cancelled with the original
Feather event keys. Python and native-library diagnostics are routed to stderr
using a duplicate of the original protocol stdout descriptor. Only the guardian
writes progress; the parent stops and reaps it before writing any terminal event,
preventing concurrent long JSON lines from interleaving on Darwin pipes. Phase
and frame counts are sent in a small atomically replaced state file. The guardian
continues independently while native inference holds Python's GIL. It describes
actual committed frames and current phase; it does not invent a quality score.
Normal forced upstream INFO and tqdm bars are suppressed so long clips do not
overflow the host stderr limit. WARNING/ERROR and Python tracebacks are retained.
FEATHER_SEEDVR2_DEBUG=1 enables full diagnostics only for development; a developer
must provide a sufficiently large stderr budget for that mode.

CPU installation smoke test (does not load weights or execute MPS):
  python worker.py --self-test
  python worker.py self-test
It checks dependencies, bounded frame ordering/counts across edge cases, actual
overlap output blending, truncated-frame rejection, 720 sizing, inherited child
process group and child reaping. It emits one completed NDJSON event. This does
not verify GPU inference, real video quality, temporal stability or FFmpeg export.

User-visible limitations
------------------------
SeedVR2 predicts texture and may change faces, lettering, logos or small patterns.
It cannot recover provable lost detail or establish identity. Motion, occlusion,
cuts and chunk boundaries may flicker, ghost or change texture. Temporal blending
reduces some discontinuity but cannot ensure accuracy. The model/runtime consumes
several GiB even though the base installer is small; rendering can be very slow.
These caveats belong in feature help/acceptance, not as claims of guaranteed repair.
